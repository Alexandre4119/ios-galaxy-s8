# Galaxy A50 port (SM-A505F, Exynos 9610)

This tree carries a second device target next to the Galaxy S8: the
**Samsung Galaxy A50 (SM-A505F, `a50`, Exynos 9610)**. It reuses the S8/A5
XNU base (`ARM64_BOARD_CONFIG_A5XELTE`) and adds the A50 board facts in a
separate XNU layer (`xnu/patches/0129-a50.patch`, generated by
`tools/a50/apply-a50.py`).

> **Status: port scaffold, not booted on a phone.** The XNU patch applies to
> the 0128 tree, the ADT generator runs, and the loader has been compiled and
> linked for AArch64 (Zig 0.17.1/clang; 32,320-byte Image, no relocations).
> It has not run on hardware, and the XNU kernel has not been built with
> `MACHINE_CONFIG=A50` yet. Treat every address below as "from Samsung's
> public device tree", not as "confirmed on this unit".

## Hardware map used

| Block | Address / fact | Source |
| --- | --- | --- |
| CPU | 4× Cortex-A53 (logical 0–3, MPIDR 0x0–0x3) + 4× Cortex-A73 (4–7, MPIDR 0x100–0x103), PSCI | `exynos9610.dts`, `a50/*` |
| GIC | GIC-400, distributor `0x12301000`, CPU interface `0x12302000` | `exynos9610.dts` |
| Timer | 26 MHz, `use-physical-timer`, PPI 14 → INTID 30 | `exynos9610.dts` |
| UFS | HCI `0x13520000`, vendor HCI `0x13521100`, UNIPRO `0x13510000`, protector `0x13530000` | `exynos9610.dts` |
| Display | DECON_F `0x148B0000`; DPP G0/IDMA `0x14891000`/`0x14881000`; IDMA0 Y address at `+0x40` | `exynos9610.dts` |
| Panel | 1080×2340 (EA8076), 32 bpp, stride 4320 | `a50/*` |
| Pinctrl | ALIVE `0x11850000` (gpa0 `+0x020`, gpa1 `+0x040`); TOP `0x139B0000` (gpp1 `+0x020`, gpg3 `+0x120`) | `exynos9610.dts` + mainline `pinctrl-exynos` |
| Keys | Power GPA1-7, Volume Up GPA1-5, Volume Down GPA1-6, active low | `a50/*` gpio-keys |
| Touch | Melfas MMS100 at `0x48` on i2c_4 `0x13870000`; IRQ GPA0-0; SCL/SDA gpp1-1/gpp1-0; enable gpg3-1; `event_info = <8 12>` | `a50/*` |
| RTC | Samsung `exynos8-rtc` at `0x11A20000`, BCD counters | `exynos9610.dts` |
| PMIC | S2MPU09 (no fuel-gauge driver in this port yet) | `a50/*` |

A50 keys and touch GPIOs are **not** the S8's. The S8 uses GPA0/GPA2 and an
S6SY761 on HSI2C; the A50 uses GPA1 and an MMS100 on i2c_4.

## What is implemented

### Boot chain

```
S-Boot (stock A50 bootloader, EL1, MMU off)
  -> BOOT partition: shim/a50 (our loader instead of a Linux Image)
     -> reads DECON IDMA0, fills boot_args.Video and patches the ADT
        "a50-fbcon" reg with the real scanout address
     -> reads the RTC at 0x11A20000 and appends a50rtc=<unix>
     -> copies the SWEETXNU payload to the 2 GiB bank at 0x880000000
     -> jumps to XNU's physical entry
        -> XNU (MACHINE_CONFIG=A50, patch 0129)
```

`tools/mkadt_a50.py` builds the Apple Device Tree. It advertises
`samsung,a50`, a 1080×2340 canvas, the A50 UFS node `a50-ufs`, and an
`a50-fbcon` node whose `reg` is a placeholder (base 0) until the loader
patches it. The loader keeps the S8's `boot_args` layout and the
`mkpayload.py` container.

### Loader (`shim/a50/`)

- `start.S` — A50 EL1 entry, vectors, PSCI CPU_OFF helper; copied from the
  S8 loader. The S8's early DECON draw and pstore marker are compiled out
  for `A50_BUILD` because the framebuffer address is runtime data here.
- `loader.c` — payload validation, copy, cache maintenance, `boot_args`,
  ADT `a50-fbcon` patch, RTC, console, probes.
- `display_probe.c` — reads DECON_F `IDMA0` `Y` at `0x14881040`, validates
  it against the low RAM window, returns it for the console/Video/ADT.
- `ufs_probe.c` — A50 UFS register bases.
- `smp_probe.c` — PSCI `CPU_ON` probe for MPIDR 0x1 and 0x100 (prints only;
  it does not start XNU's secondary cores).

### XNU layer (`0129-a50.patch`)

- `MakeInc.def`, `bsd/conf`, `libkern/conf`: A50 is added to the machine
  filters that keep the kernel plain `arm64` (not arm64e), the compact 4 KiB
  VA layout, and the built-in pthread/HFS/BearSSL sources. Without these,
  `MACHINE_CONFIG=A50` builds the wrong arch or misses objects.
- `config/MASTER.arm64.a50`: A50's copy of the a5xelte kernel options;
  `doconf -soc a50` selects it.
- `A5XELTE.h`: `A50_BUILD` selects the A50 constants (1080×2340, DECON
  `0x148B0000`, UFS node `/a50-ufs`, physical timer INTID 30, GPA1 keys,
  no Home key). The S8 block is untouched.
- `start.s`: the S8-only early framebuffer marker/block is skipped for A50.
- `SweetFramebuffer.cpp`: A50 takes the physical address from
  `boot_args.Video` (the loader), and the DECON map uses `A5_DECON_BASE`.
- `pe_serial.c`: looks up the loader-patched `a50-fbcon` node.
- `a5xelte_keys.c`: GPA1 at ALIVE + 0x040, pins 7/5/6, no fourth key.
- `a5xelte_touch.c`: appends `tools/a50/a50_touch.c`. The MMS100 driver
  bit-bangs i2c_4 on gpp1-0/1 instead of touching the Exynos9610 HSI2C
  clock gates, which are not documented in the public DT.
- `IOPlatformExpert.cpp`: accepts `a50rtc=` (and still `s8rtc=`).
- `SweetBattery.cpp`: no A50 gauge yet; publishes a static 100%/AC source.
- `sweet_ufs.c`: uses `A5_UFS_NODE` (`/a50-ufs`).
- `KernelConfigTables.cpp`: matches `samsung,a50` and
  `samsung,a50-display`.

## Known gaps / risks

1. **Never booted.** The loader links for AArch64, but neither the canonical
   `aarch64-linux-gnu-gcc` build nor an XNU `MACHINE_CONFIG=A50` build has
   been run, and no image has been flashed.
2. **Panel geometry.** SweetFramebuffer presents the native 1080×2340
   canvas (3× = 360×780 pt), not the iPhone X's 1125×2436. SpringBoard and
   the iPhone X userland may lay out incorrectly. Do not force
   `sweetfb_native=1` as a fix until the native path is known to work.
3. **Touch timing.** Bit-banged I2C has no error recovery beyond retries and
   no controller interrupt registration; the thread polls GPA0-0. If S-Boot
   leaves gpp1 in a non-GPIO function, the first transaction will not ACK.
4. **Scanout address width.** `display_probe.c` reads IDMA0 Y as 32 bits.
   If S-Boot's logo buffer is above 4 GiB (the A50 has 4/6 GiB), the high
   bits are lost and the probe may reject or mis-point the console. The
   DECON high-address register is not documented in the public DT.
5. **UFS.** The A50's UFS is at the same class of addresses as the S8 but
   the GPT layout and the USERDATA partition number/LUN are not verified.
   `ufsroot=USERDATA` is the default; the A50 may name it differently.
6. **Battery** is a static source; S2MPU09 register work is not done.
7. **No pstore/ramoops.** The loader and kernel only log to the panel. A
   crash before the framebuffer is up is invisible.
8. **Secondary cores.** The A73 cluster needs its power/L2 bring-up; only
   the PSCI probe exists here. Start with `cpus=1`.
9. **Model string.** The ADT says `iPhone10,3` because the userland is the
   iPhone X 16.7.16 root. This is a userland compatibility choice, not an
   A50 hardware fact.

## Verification performed

- `tools/a50/apply-a50.py` runs on the 0128 tree with all anchors matching.
- `xnu/patches/0129-a50.patch` (14 files, 773 lines, including the new
  `config/MASTER.arm64.a50`) applies to a fresh 0128 tree with `patch -p1`;
  the result is byte-identical (after newline normalization) to the
  generated tree.
- `tools/mkadt_a50.py` emits a 9520-byte ADT with `a50-fbcon`, `a50-ufs`,
  `samsung,a50` and the 1080×2340 canvas.
- `gcc -fsyntax-only` (host, x86-64) accepts `loader.c`, `ufs_probe.c`,
  `smp_probe.c` and `display_probe.c`.
- Zig 0.17.1 (`zig cc -target aarch64-freestanding -mcpu=cortex_a53`)
  compiles `start.S`, `loader.c` and `fdt.c` plus all three probes, links
  them with `loader.ld`, and `zig objcopy` produces a 32,320-byte Image.
  The ELF reports `EM_AARCH64`, entry `_head` at 0, `_start` at 0x800, no
  relocation sections and no `R_AARCH64_ABS64`.
- Not run: the canonical `aarch64-linux-gnu-gcc` build, an XNU
  `MACHINE_CONFIG=A50` build, any device boot.
